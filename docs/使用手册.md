# 使用手册

## 快速开始（动态插件方式，当前会话）

1. 在本会话中已运行动态插件 `hanhu-1`（v15 · token 优化版），工具 `hanhua_scan/parse/translate/qa/glossary/export/config` 已可用。
2. 把游戏目录放到工作区（或 `hanhua_config set root <游戏目录>`）。
3. 依次调用：
   - `hanhua_scan` — 扫描项目，列出可汉化文件
   - `hanhua_parse` — 提取全部文本（`errors` 字段列出失败文件及原因）
   - `hanhua_glossary add` — 添加术语（人名/地名/道具名务必先加入，保证全文统一）
   - `hanhua_translate` — 词典/缓存优先，在线 API 兜底；自动跳过无字母/高 CJK 条目、同语境去重、按 `apiChunk` 分批
   - `hanhua_qa` — 检查占位符/换行/长度/漏译
   - `hanhua_export mode=inplace` — 写回并自动生成 `<file>.bak` 备份
4. 浏览器「设置 → 汉化工作台」提供按钮化的一键全流程与词典管理。

## Token 优化

在保证译文符合语境的前提下尽量少消耗 token（在线 API 与对话上下文都算）：

- **智能过滤**：无字母（纯数字/符号）或中日韩字符占比 ≥ 50% 的条目直接跳过（method=`skip`），不产生 API 调用
- **语境去重**：相同「原文 + 语境」只翻译一次，其余条目复用首条译文（语境标签：名称/选项分支/地图对话/剧本对话/系统术语等）
- **压缩提示词**：API 请求按紧凑的 `[语境, 原文]` 对发送
- **分批**：`hanhua_config set apiChunk=40` 控制每批条数（1-100，越大越省提示词开销，响应也更长）
- **紧凑预览**：`hanhua_parse` 返回 ≤20 条预览 + perFile 统计；`hanhua_translate` 只返回有实际变更的 ≤20 条

## 引擎专属要点

### RPG Maker XP / VX / VX Ace / mkxp-z（RGSS）
- 支持：`Map*.rxdata/.rvdata/.rvdata2`（事件名 + 101 对话 / 401 续行 / 102 选项 / 402 分支 / 408 注释）、`Actors/Classes/Skills/Items/Weapons/Armors/Enemies/States/Troops`（名称/描述/消息数组）、`System`（标题/货币/术语表）、`CommonEvents`（名称+命令列表）。
- `Scripts.*` 一律跳过（脚本代码不翻译）。
- 字符串编码：VX Ace 多为 UTF-8；XP/VX 中文游戏多为 GBK、日文游戏多为 Shift-JIS。乱码时用 `hanhua_config set rgssEncoding=gbk`（或 shift_jis）。
- 写回保持 Ruby Marshal 4.8 原格式（对象/符号/链接/Table 原样保留），引擎可正常加载。

### krkr / KAG
- 支持 `.ks/.scn`（裸文本行 + `text/name/title/label/hint/message/caption` 属性值）、`.tjs`（行首引号字符串）、`.csv/.txt`。
- 编码自动识别：UTF-16LE(BOM) → UTF-16BE(BOM) → UTF-8 → Shift-JIS → GBK；写回按原编码。
- Shift-JIS/GBK 写回需要 iconv-lite：`hanhua_config set iconvPath=<iconv-lite 绝对路径>`。
- 打包在 `.xp3` 里的脚本请先用外部工具（如 GARbro/krkrextract）解包再处理。

## 常见问题

- **解析 0 条目且 errors 有 "not found"**：`root` 参数拼错或相对路径不对；用绝对路径。
- **翻译结果残留英文**：正常——词典未覆盖且未配置在线 API。配置 `apiUrl/apiKey` 后自动补全。
- **导出报 subprocess 错误**：DSH 宿主的 `subprocess` 服务不可用；二进制回写依赖 node 子进程。
- **.bak 文件**：inplace 模式的自动备份，出问题直接覆盖回原名即可还原。
