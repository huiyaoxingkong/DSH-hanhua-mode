# 使用手册

> 版本 2.0.0。功能原理与限制见 [v2 多媒体与 OCR](V2-多媒体与OCR.md)；
> 内核兼容与安装见 [README](../README.md)。

## 快速开始

### 1. 安装

- **桌面版（0.2.0-rc.2）**：`node tools\install-hanhua-desktop.mjs` → 重启 DSH → 新建会话选「汉化模式」。
- **旧内核（0.1.6-alpha.2）**：把 `preset/` 复制为 `${DSH_HOME:-~/.dsh}/.agent-presets/hanhua/` → 新建会话选「汉化模式」。

### 2A. 游戏文本

```
hanhua_config set root <游戏目录>
hanhua_scan                       # 扫描 + 分类统计
hanhua_parse                      # 提取文本（errors 列出失败文件）
hanhua_glossary add ...           # 人名/地名/道具名先入词典，保证全文统一
hanhua_translate                  # 词典/缓存优先，在线 API 兜底
hanhua_qa                         # 占位符/换行/长度/漏译
hanhua_export mode=inplace        # 写回并自动 <file>.bak
```

### 2B. 视频字幕

```
hanhua_scan                       # 分类统计里会看到 subtitle / video
hanhua_parse                      # .srt/.vtt/.ass/.ssa/.lrc/.sub/.smi 解析（时间轴不动）
hanhua_translate → hanhua_qa → hanhua_export
# 内嵌字幕轨（需要本机 ffmpeg）：
hanhua_media action=subs-list file=ep01.mkv
hanhua_media action=subs-extract file=ep01.mkv out=ep01.srt
#   … 对 ep01.srt 走一遍 parse/translate/export …
hanhua_media action=subs-mux file=ep01.mkv sub=ep01.srt out=ep01.zh.mkv
```

* ASS/SSA 的覆写标签（`{\an8}`、`\N`、`\h`）会被换成 `⟦n⟧` 占位符送翻译，回写自动还原；
  `Comment:` 行、`[V4+ Styles]`、`Format:` 行一律不动。
* 字幕是「一行一句」，翻译提示词里带 `字幕` 语境标签，模型会按简洁口语处理。

### 2C. 电子书

```
hanhua_parse                      # .epub（按 opf spine 顺序）/ .html / .pdf
hanhua_translate → hanhua_qa → hanhua_export
```

* EPUB 导出是**整包重打包**：条目顺序、`mimetype`（第一个且 store）与各条目压缩方式都保留，原包备份为 `.bak`。
* PDF 只输出 `.hanhua-out/<书名>.hanhua.txt` 译文对照（不回写 PDF）；若是扫描件，
  `hanhua_parse` 的 errors 会提示改用 `hanhua_ocr`。

### 2D. 漫画与图片艺术字（OCR）

```
hanhua_ocr layout=manga           # 漫画页：气泡检测 + 本地 OCR + 视觉兜底
hanhua_ocr layout=art             # 图片艺术字/标题/logo：放宽尺寸、整页兜底
hanhua_ocr files=["art/title.png"] budget=0   # 只用本地引擎（0 token）
hanhua_translate → hanhua_qa → hanhua_export  # 导出=擦除原文 + 自动字号排版
```

* 首次跑完会写 `.hanhua-ocr-cache.json`；**再跑同一批图 0 调用、0 token**。
* `budget` 是「本次最多让视觉模型看几张图」，超出的区域留到下次（已识别的命中缓存）。
* `hanhua_usage` 看账本：本地 OCR 命中多少、视觉花了几张、省了多少。

## Token 优化

- **智能过滤**：无字母（纯数字/符号）或中日韩占比 ≥ 50% 的条目直接跳过，不产生 API 调用。
- **语境去重**：相同「原文 + 语境」只翻译一次（语境标签：名称/选项/剧本对话/字幕/气泡/艺术字…）。
- **压缩提示词**：API 请求按紧凑的 `[语境, 原文]` 对发送；`apiChunk`（1–100）控制每批条数。
- **本地 OCR 优先**：中文/英文常规字走 Windows 内置 OCR（0 token）；只有本地识别不可信的区域才调视觉模型。
- **OCR 缓存 / 裁剪去重 / 视觉预算**：见 [v2 文档 §2.3](V2-多媒体与OCR.md)。
- **紧凑预览**：所有工具只返回 ≤20 条预览 + 统计。
- **账本**：`hanhua_usage` 复核真实用量（API/视觉 token、缓存命中、去重、跳过）。

## 引擎专属要点

### RPG Maker XP / VX / VX Ace / mkxp-z（RGSS）
- 支持：`Map*.rxdata/.rvdata/.rvdata2`（事件名 + 101 对话 / 401 续行 / 102 选项 / 402 分支 / 408 注释）、`Actors/Classes/Skills/Items/Weapons/Armors/Enemies/States/Troops`（名称/描述/消息数组）、`System`（标题/货币/术语表）、`CommonEvents`（名称+命令列表）。
- `Scripts.*` 一律跳过（脚本代码不翻译）。
- 字符串编码：VX Ace 多为 UTF-8；XP/VX 中文游戏多为 GBK、日文游戏多为 Shift-JIS。乱码时
  `hanhua_config set rgssEncoding=gbk`（或 shift_jis）。
- 写回保持 Ruby Marshal 4.8 原格式（对象/符号/链接/Table 原样保留），引擎可正常加载。

### krkr / KAG
- 支持 `.ks/.scn`（裸文本行 + `text/name/title/label/hint/message/caption` 属性值）、`.tjs`（行首引号字符串）、`.csv/.txt`。
- 编码自动识别：UTF-16LE(BOM) → UTF-16BE(BOM) → UTF-8 → Shift-JIS → GBK；写回按原编码。
- Shift-JIS/GBK 写回需要 iconv-lite；桌面版安装已把 iconv-lite 放进插件 `node_modules/`，通常无需配置。
- 打包在 `.xp3` 里的脚本请先用外部工具（GARbro/krkrextract）解包再处理。

### 字幕编码
- `.srt/.ass` 常见 UTF-8 或 UTF-16LE（BOM）；日文字幕常见 Shift-JIS。引擎自动识别，
  写回按原编码；异常时用 `hanhua_config set subtitleEncoding=shift_jis`。

## 常见问题

- **解析 0 条目且 errors 有 "not found"**：`root` 参数拼错或相对路径不对；用绝对路径。
- **翻译结果残留英文**：词典未覆盖且在线 API 未配置/失败；`hanhua_config set apiUrl/apiKey` 后重跑，
  或用 `hanhua_usage` 看 `lastError`。
- **在线 API 报连接错误**：v2 的 API 走 node 子进程 fetch（`ctx.web.fetch` 发不出 POST）。
  若本机无外网，配置本地/内网 OpenAI 兼容端点即可。
- **导出报 subprocess 错误**：DSH 宿主的 `subprocess` 服务不可用；二进制回写与外部工具都依赖它。
- **图片没被 OCR 到**：`hanhua_media action=probe` 看本地 OCR/Python 是否可用；
  艺术字用小字号时本地引擎不可靠，加大 `budget` 让它走视觉模型，或 `layout=art` 重跑。
- **区域漏检/误合**：调整 `layout`（manga/art/auto）、`ocrMinArea`、`ocrMaxRegions`，
  然后 `hanhua_ocr force=true` 忽略缓存重跑指定文件。
- **`.bak` 文件**：inplace 模式的自动备份（写一次即固定），出问题直接覆盖回原名即可还原。
- **`.hanhua-tmp/` 与 `.hanhua-*.json`**：子进程脚本、裁剪图与状态文件，可安全删除
  （删掉 `.hanhua-ocr-cache.json` 会丢失 OCR 缓存，下次重新识别会再花一次成本）。
